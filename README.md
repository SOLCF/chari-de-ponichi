# チャリでポンイチ

自転車の走行距離をGPSで積み上げて、日本一周（12,000km）を目指すアプリ。
走り切ったら世界一周 → 月旅行 → 火星旅行 → 1光年、と目標が続いていく。

ビルド不要の PWA。素の HTML / CSS / JavaScript だけで動き、外部ライブラリも CDN も使っていない。

---

## 動かす

### スマホで使う（本番）

Geolocation API と Service Worker は HTTPS でしか動かないため、どこかに置く必要がある。
GitHub Pages が手軽（無料・HTTPS・Git だけで完結）。

```bash
cd "F:/Claude/チャリでポンイチ" && git init && git add -A && git commit -m "チャリでポンイチ" && git branch -M main
```

そのあと GitHub でリポジトリを作り、

```bash
git remote add origin https://github.com/<ユーザー名>/chari-pon-ichi.git && git push -u origin main
```

リポジトリの Settings → Pages → Source を `main` / `/ (root)` にすると
`https://<ユーザー名>.github.io/chari-pon-ichi/` で開ける。

Android Chrome でそのURLを開き、メニューから **「ホーム画面に追加」**。
アイコンから起動すればアドレスバーの無い全画面で動く。

初回の走行開始時に位置情報の許可を求められるので「許可」を選ぶ。

### PC で動作確認する

```bash
powershell -ExecutionPolicy Bypass -File tools/serve.ps1
```

`http://localhost:8000` を Chrome で開く。localhost は安全なコンテキストとして扱われるので、
ここからなら位置情報も Service Worker も動く。

実際に走らなくても、Chrome DevTools の **Sensors** パネル
（F12 → 右上の ⋮ → More tools → Sensors）で現在地を手動で動かせば、
スタートから距離の積算までを一通り試せる。

止めるときは Ctrl+C。ポートを変えたいときは `-Port 8080` を付ける。

### 計測ロジックを検証する

`test/geo.test.html` をブラウザで開くだけ（サーバ不要、ファイルを直接開いてよい）。

模擬した測位点の列を `js/geo.js` に流し込み、23項目を検証する。
乱数は固定シードなので結果は毎回同じ。

- 距離計算そのものの正しさ（東京駅→横浜駅が約27.3kmになるか、など）
- 素直な走行で距離を削っていないか
- **停車中に距離が増えないか**（このアプリで最も重要）
- ワープや低精度点をはじけているか
- 中断をはさんでも復帰できるか
- **設定値を振ったときにフィルタが効いているか**
  （上限速度を下げると距離が減る／下限速度を0にすると徐行ぶんが乗り始める）

`js/geo.js` を触ったら必ずこれを開くこと。

## 距離の測りかた

GPS は静止していてもふらつくので、素朴に全点を足すと**停車中でも距離が増え続ける**。
そこで測位点ごとに次の順で採否を判定している（`js/geo.js` の `evaluate`）。

1. `accuracy` が **精度しきい値** より粗い点は捨てる
2. 前回採用点からの距離が **両点の accuracy の和** 未満ならノイズとして捨てる
3. 実効速度が **上限速度** を超えたらGPSの飛びとして捨てる
4. 実効速度が **下限速度** 未満なら停止中として加算しない
5. 残ったぶんだけ Haversine 公式で加算する

### 基準点を据え置く

2〜4で捨てたとき、基準点（anchor）は**動かさない**。これが設計の要。

- ゆっくり進んだ場合、変位が基準点から積み上がっていき、いずれしきい値を超えて**まとめて加算される**。
  つまり低速走行でも距離を取りこぼさない。5秒間隔のような細かい設定でも合計が合う。
- 本当に静止している場合、変位は伸びないので `距離 ÷ 経過時間` が 0 に収束し、
  いつまでも棄却され続けてドリフトが乗らない。

ただしこのままだと、アプリがバックグラウンドに落ちて遠く離れた場所で復帰したとき、
延々と「飛び」と判定され続けて復帰できなくなる。
そのため **中断とみなす時間** を超えた空白があったら、距離を加算せずに基準点だけ現在地へ移す。

### 取得間隔

- **10秒以下** … `watchPosition` を回しっぱなしにする。毎回起動し直すより、GPSを温かい状態に保つ方が電力効率が良い
- **10秒より長い** … 1点取ったらGPSを解放し、次の周期まで休ませる（デューティサイクル）

間隔が長いほど曲がり角をショートカットするので距離は短めに出る。設定画面に目安を書いてある。

## 設定できること

| 項目 | 既定値 | 範囲 |
|---|---|---|
| GPS取得間隔 | 15秒 | 5〜300秒 |
| 上限速度 | 60 km/h | 20〜1000 km/h |
| 下限速度 | 1.5 km/h | 0〜10 km/h |
| 精度しきい値 | 30 m | 5〜100 m |
| 中断とみなす時間 | 300秒 | 60〜1800秒 |

上限速度を **1000 km/h** まで上げると実質フィルタなしになり、飛行機の移動まで距離に乗る。
精度を捨ててでも旅そのものを記録したいとき用。逆に 40 まで下げれば、車や電車の移動が混ざりにくくなる。

このほか、各章の目標距離の変更（マイルストーンの位置も比例して伸縮する）、
距離の手動補正、バックアップの保存と復元ができる。

## いまの制約

ブラウザがバックグラウンドに回ると測位は止まる（Webの仕様上どうにもならない）。
そのため走行中は Screen Wake Lock API で画面を点けたままにしている。**ハンドルに固定して使う前提**。

中断が起きた場合は復帰時にトーストで知らせ、中断中の移動は距離に加算しない。
取りこぼしたぶんは設定画面の「距離の手動補正」で足せる。

## この先

ポケットに入れて画面オフのまま計測したくなったら、Capacitor でネイティブ化する。
そのために次を守ってある。

- 位置情報を触るのは `js/tracker.js` の中だけ。他から `navigator.geolocation` を呼ばない
- 保存は `js/store.js` 経由のみ
- パスはすべて相対。外部ライブラリ・CDNへの依存なし

移行時は `tracker.js` の測位部分を background-geolocation プラグインに差し替え、
`store.js` を Preferences か SQLite に向ければよい。UI とロジックはそのまま使える。
